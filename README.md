# project-implementation-RD

Repository for the research and development work on the 247-519-VA (Project I) project at Vanier College: an ESP32-based smartwatch and custom waist-worn system for fall detection and caregiver alerting.

## Contents

### `documents/proposal/`
The written Project Proposal, built in LaTeX.

- `proposal.tex` main document; pulls in the table files below via `\input`.
- `table1_stakeholder_needs.tex` to `table5_uncertainties.tex` the proposal's tables.
- `Proposal.pdf` compiled output.

### `figures/generated/`
- `context_diagram.pdf` system context diagram, generated by `src/context_diagram.py`.
- `watch_functional_block_diagram.png` watch functional block diagram.

### `src/`
- `context_diagram.py` regenerates the context diagram.
- `watch_WiFi_OLED_test/` Wi-Fi and display bring-up sketch for the watch.
- `FallDetector_trials/` watch firmware: IMU sampling at 238 Hz, impact-triggered fall classifier, on-screen status, and SD logging with button-marked test trials.
- `fall_model/` training pipeline for the classifier (FallAllD to features to random forest to C header) and a C-versus-Python parity check.
- `session_analysis/` tools that clean and score the SD card logs from watch test sessions.

### `data/`
- `features/` outputs of the training pipeline (`features.csv`, `wrist_windows.csv`, feature order, Python reference windows for the parity check).
- `sessions/` watch test logs, original and cleaned, plus the raw IMU recordings.
- `fallalld/` instructions for recreating the FallAllD subset (the data itself is not committed).

## Reproducing the wrist fall model

Requires Python 3 with the packages in `requirements.txt` (tested with Python 3.13, numpy 2.5, pandas 3.0, scipy 1.18, scikit-learn 1.9) and gcc for the parity check. Run from the repository root; the scripts locate files relative to themselves.

1. Create the FallAllD subset as described in `data/fallalld/README.md`.
2. `python src/fall_model/build_features.py` whole-trial features and the subject split to `data/features/features.csv`.
3. `python src/fall_model/baseline.py` optional whole-trial baseline (waist vs wrist, with and without barometer).
4. `python src/fall_model/wrist_windows.py` impact windows and the 14 features to `data/features/wrist_windows.csv`.
5. `python src/fall_model/wrist_classify.py` cross-validated threshold and test-subject evaluation.
6. `python src/fall_model/export_c.py` trains the deployed model and writes `src/FallDetector_trials/fall_model.h`.
7. `python src/fall_model/parity_test/parity_check.py` checks that the C detector matches the Python model.

Model summary: trigger at 2.5 g, window of 1 s before and 2 s after the peak, 14 features, random forest of 100 trees (depth 6), decision threshold 0.26, subjects split 9 train, 3 validation, 3 test. On the three held-out test subjects: 2.8% of 71 falls missed, 9.8% of 338 non-fall trials raised an alarm.

## Watch test sessions

`python src/session_analysis/clean_sessions.py` writes the clean logs; `python src/session_analysis/analyze_session.py` scores them.

| Session | Trials | Result |
| --- | --- | --- |
| events_001, real falls | 20 | 19 detected, 1 missed (5.0%) |
| events_002, non-falls | 10 | 8 false alarms (80%) |

The false-alarm rate is far above the under-10% target on the wearer's wrist. Retraining on the watch's own recordings is the next step.

## Status

The proof-of-concept wrist detector runs on the watch and logs test trials to SD. The MQTT alert path, the waist board with barometer and the 60 s inactivity check are not implemented yet.
